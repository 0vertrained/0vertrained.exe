# iOS application audit · November 28, 2026

The audit started from `addabdb` on the `ios` branch. High priority denotes a risk to athlete privacy, workout records or a server trust boundary. Medium priority denotes a broken workflow, a misleading interface or a development-tool exposure.

## Security and privacy

| Priority | Confirmed issue | Repair and evidence |
| --- | --- | --- |
| High | Progress photos used one album for everyone on an iPhone. | Native album operations now require an athlete UUID. Switching profiles clears the displayed images, and an older app build cannot open the shared album through the new interface. Swift fixtures read and delete identical photo IDs under two owners independently. |
| High | A signed-out athlete’s training and Oura bedtime reminders could remain on a shared phone. Their switches, plan and bedtime text also used shared storage. | Preferences and personal content are scoped by athlete. A change of owner invalidates pending writers and clears the app’s reminders. The rebuilt native app also clears delivered reminders. Tests cover sign-out during an in-flight update and a second athlete on the same phone. |
| High | Oura, Strava and WHOOP could accept an OAuth callback after a state lookup even when the separate deletion failed. | One database operation now claims an unexpired state and returns its owner. Tests cover overlapping callbacks, expired state and failed claims. |
| High | Web push accepted arbitrary delivery destinations and scheduled senders trusted the stored address. | Registration and both delivery paths now validate the HTTPS push service. Tests cover supported destinations, rejected destinations and removal of obsolete subscriptions. |
| Medium | Wearable and push failures could copy private upstream error bodies into application logs. | Affected handlers now log operational fields such as status and data type. Tests check that the upstream body stays out of logs. |
| Medium | The npm advisory service flagged 17 packages in the development dependency tree. | Updated the lockfile within the declared application dependencies. The full-tree and production-only advisory checks both returned zero findings for the release lockfile. |
| High | A backup operation that outlasted an account switch could finish reading, sharing or restoring the previous athlete’s data. | Backup operations now capture an account session, filter each history page by owner, and check that the session is still current before writing, sharing or opening an export preview. |

## Workout data and reliability

| Priority | Confirmed issue | Repair and evidence |
| --- | --- | --- |
| High | Apple Health imports could be marked handled before the workout reached durable offline storage. | Imports now enter the offline queue first. A rejected write leaves the workout eligible for another import. |
| High | Undoing a Health import could erase a prior climb’s distance, time and activity links, or later changes to effort and splits. | Undo restores the previous fields that the import still owns and preserves subsequent edits. The regression starts with a linked climb, imports the run, edits it, and then undoes the import. |
| Medium | A failed HealthKit detail lookup blocked splits and effort from arriving for later workouts. | Detail requests now recover independently. The regression fails one lookup and verifies that a different workout still receives its details. |
| High | A second window could delete a course needed to recover an active workout, including a previous section in a repeated climb. | Course deletion now checks the stored workout and its previous attempts during the same IndexedDB transaction. Once the workout is finished, the course can be removed. |
| Medium | A fallback climb library could disappear when IndexedDB became available again. A storage quota error could leave half of a multi-attempt save visible. | Existing local records preserve the storage choice. A failed local batch rolls back completed writes. Tests cover returning to a legacy library and running out of storage on the second result. |
| Medium | The supplied database schema rejected Oura authorization states. | Updated the fresh-install schema and added migration v36 for deployed databases. Isolated PostgreSQL tests applied the upgrade twice, preserved an existing Strava state and accepted Oura. |
| Medium | Malformed backup files could crash the importer or load invalid workout records. A partial post-import reload could displace other days already on the device. | Both demo and account imports validate the backup before applying it. The account import preserves unrelated local records. |
| Medium | CSV exports dropped recorded zeroes, broke columns on commas or quotes, and could give spreadsheet software an expression where the athlete entered text. | The exporter preserves numeric zero, escapes fields, and treats formula-like text as text. An app-generated 140-day JSON backup and historical workouts with empty set slots were also checked for compatibility. |

## UI and UX

| Priority | Confirmed issue | Repair and evidence |
| --- | --- | --- |
| High | A destructive confirmation could accept a held Enter key. Concurrent confirmation requests or closing the screen could strand a waiting action. | Cancel receives initial focus for destructive actions. Held Enter is ignored, the focused button determines the action, and pending confirmations resolve on dismissal or unmount. |
| High | Deleting a photo could report success after file removal failed. An unreadable album index was treated as an empty album. | Native errors now propagate. The index remains available for a deletion retry, and the gallery offers recovery when loading or removal fails. Swift tests cover damaged indexes and partial deletion. |
| Medium | A comparison could show an old photo under a newly selected date. | Changing the selection clears the previous image immediately and distinguishes an unavailable photo from one still loading. |
| Medium | Reminders could appear scheduled even after iOS denied permission or failed to add them. | Scheduling waits for the native result, reports failure and allows retry. A denied request cannot populate the successful schedule cache. |
| Medium | Cancelling the native share sheet could trigger a fallback download of the backup. | Explicit cancellation ends the export without opening another delivery path. |

## Rollout and verification limits

The bundled demo was exercised in Apple WebKit at 320 and 744 pixels across Today, Train, Fuel, Progress, Log and Profile. All twelve screen checks had reachable content, named visible controls and no horizontal overflow. The photo and confirmation flows were also checked at 382 pixels. The iPhone and Watch simulator targets compiled with the pinned Capacitor frameworks.

Rebuild the iPhone app for private albums and native reminder handling. Photos from older builds remain on the phone. The athlete can import the older collection into their chosen profile after device authentication. Reminder switches saved by older builds had no owner and need a one-time opt-in for each athlete.

Existing Supabase databases using the earlier provider constraint need the v36 migration. It was exercised on an isolated PostgreSQL instance. Production database access, physical biometric prompts, HealthKit authorization, wearable pairing and external provider sign-in were outside the verification environment.
